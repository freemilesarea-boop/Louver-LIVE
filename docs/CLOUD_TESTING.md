# Louver Live Cloud — 직접 테스트하기

이 문서 하나만 따라 하면 브라우저에서 영상을 올리고 YouTube로 실제 방송을
시작할 수 있습니다. 코드나 API를 몰라도 됩니다.

---

## 먼저: 지금 어디서 돌리고 있나

화면 맨 위에 항상 둘 중 하나가 표시됩니다.

| 표시 | 뜻 |
| --- | --- |
| **LOCAL DEVELOPMENT** | 서버가 **이 컴퓨터**에서 돌고 있습니다. 노트북을 닫거나 끄면 **방송도 끝납니다.** 정상입니다. |
| **REMOTE CLOUD SERVER** | 서버가 **계속 켜져 있는 리눅스 서버**에서 돌고 있습니다. 브라우저를 닫아도, 내 컴퓨터를 꺼도 방송은 계속됩니다. |

Mac에서 아래 "로컬 실행"으로 띄우면 **LOCAL DEVELOPMENT**입니다. 브라우저를
닫아도 방송이 유지되는지는 확인할 수 있지만(서버 프로세스는 계속 살아 있으므로),
**컴퓨터를 끄면 방송도 끝납니다.** 컴퓨터를 꺼도 유지되는지 보려면 아래
"VPS 배포"로 서버에 올려야 합니다.

---

## A. 로컬 실행 (Mac / Linux)

준비물: Node 20+, Rust(cargo), 그리고 인터넷. FFmpeg는 알아서 받아옵니다.

### 1. 서버 실행

```bash
npm install          # 처음 한 번
npm run cloud:dev
```

처음에는 서버를 빌드하느라 몇 분 걸립니다. 끝나면 이렇게 나옵니다.

```
──────────────────────────────────────────────
  LOCAL DEVELOPMENT
  http://127.0.0.1:8080
  이 컴퓨터를 끄거나 이 창을 닫으면 방송도 끝납니다.
──────────────────────────────────────────────
```

이 창은 **켜 둔 채로** 둡니다. 창을 닫으면 서버가 종료됩니다.

데이터(데이터베이스, 업로드한 영상, 스트림 키를 봉인하는 master key)는 전부
`.louver-dev/` 안에 들어갑니다. 이 폴더는 git에 올라가지 않습니다.

### 2. 계정 만들기

브라우저에서 바로 "계정 만들기"로 가입할 수 있습니다. 다만 그렇게 만든 계정은
**Basic**이라 동시 방송이 1개입니다. 동시 3개를 테스트하려면 **Business**로
만드세요. 새 터미널에서:

```bash
npm run cloud:user -- me@example.com --plan business
```

비밀번호는 입력할 때 화면에 보이지 않습니다(10자 이상). 이미 있는 계정에 같은
명령을 쓰면 요금제만 Business로 바뀝니다.

> 기본 비밀번호 같은 건 없습니다. 이 저장소 어디에도 계정이 미리 들어 있지
> 않고, 비밀번호는 명령줄 인자로 받지 않습니다(`ps`와 셸 기록에 남기 때문).

### 3. 브라우저에서 방송하기

1. <http://127.0.0.1:8080> 접속
2. 로그인
3. **영상** 탭 → "영상 추가" → mp4 선택 → 상태가 `사용 가능`이 될 때까지 기다림
   (90분짜리는 몇 분 걸립니다. 업로드가 끝나면 목록에는 바로 보입니다.)
4. YouTube Studio → 만들기 → 실시간 스트리밍 시작 → **스트림 키 복사**
5. **송출 대상** 탭 → "대상 추가"
   - 이름: 아무거나 (예: 내 채널)
   - 서버 주소: `rtmps://a.rtmps.youtube.com/live2` (이미 채워져 있습니다)
   - 스트림 키: 4번에서 복사한 값
   - 저장하면 목록에는 `••••••••••••` 만 보입니다. 키는 다시 볼 수 없습니다.
6. **방송** 탭 → "방송 만들기" → 영상과 송출 대상을 고르고 만들기
7. **시작** 클릭
8. YouTube Studio 화면에 몇 초 뒤 영상이 들어옵니다. 들어오면 "실시간 시작"을
   누르면 공개 방송이 시작됩니다.
9. 끝낼 때는 Louver Live에서 **중지**

### 4. 서버 상태 보기

**서버 상태** 탭에 방송별로 다음이 나옵니다.

- 송출 시간, 전송량, 평균 비트레이트, 재시작 횟수, FFmpeg PID, 마지막 오류
- 서버 CPU / 메모리 / 디스크 여유 / 누적 송출량
- `api · database · ffmpeg · storage` 각각의 상태

같은 내용을 명령줄에서도 볼 수 있습니다.

```bash
curl -s http://127.0.0.1:8080/health
```

## B. VPS 배포 (컴퓨터를 꺼도 유지되는 진짜 테스트)

리눅스 서버(Ubuntu 22.04 이상, Docker 설치)에서:

```bash
git clone <이 저장소> louver && cd louver
cp .env.example .env
# .env 를 열어 LOUVER_MASTER_KEY 를 채웁니다:
#   openssl rand -hex 32
docker compose up -d --build
```

`docker compose up` 한 번으로 Web, API, 데이터베이스(SQLite), Broadcast
Manager, FFmpeg Worker가 전부 한 컨테이너에서 실행됩니다.

계정 만들기:

```bash
docker compose exec -e LOUVER_BOOTSTRAP_PASSWORD='내가정한긴비밀번호' \
  louver louver-server --create-user me@example.com --plan business
```

접속은 `http://<서버IP>:8080`. 화면 맨 위에 **REMOTE CLOUD SERVER**가 보이면
제대로 올라간 것입니다.

> **HTTPS**: 그대로 열면 평문 HTTP입니다. 인터넷에 공개할 거라면 Caddy나 Nginx를
> 앞에 두고 TLS를 붙이세요. 세션 쿠키는 기본적으로 `Secure`라서 HTTPS에서 제대로
> 동작합니다. (로컬 개발 스크립트만 이 플래그를 끕니다.)

| 확인 | 값 |
| --- | --- |
| 상태 | `curl -s http://<서버IP>:8080/health` |
| 로그 | `docker compose logs -f louver` |
| 데이터 | `louver-data` 볼륨 (데이터베이스 + 영상). 백업 대상은 이미지가 아니라 이 볼륨입니다. |

`LOUVER_MASTER_KEY`를 잃어버리면 저장해 둔 스트림 키를 전부 다시 입력해야
합니다. 이미지 안에는 들어 있지 않습니다(레지스트리에 키를 같이 배포하는 셈이
되므로).

## C. 직접 해 볼 테스트

| 테스트 | 하는 법 | 기대 결과 |
| --- | --- | --- |
| **A. 브라우저 종료 후 유지** | 방송 시작 → 브라우저 완전히 종료 → 다시 접속 | 여전히 `송출 중` |
| **B. 컴퓨터 종료 후 유지** | VPS 배포에서 방송 시작 → 내 컴퓨터 종료 → 휴대폰으로 YouTube 확인 | 방송 계속 (LOCAL에서는 끝나는 게 정상) |
| **C. 동시 3개** | Business 계정으로 서로 다른 스트림 키 3개 등록 → 3개 시작 | 대시보드 `3 / 3`, 4번째 시작은 요금제 한도로 거절 |
| **D. FFmpeg 강제 종료** | 서버 상태 탭에서 PID 확인 → `kill -9 <PID>` | 그 방송만 `재연결 중` → `송출 중`, 나머지는 그대로 |
| **E. 서버 재시작** | `docker compose restart louver` (또는 로컬에서 Ctrl-C 후 재실행) | `desired_state=running`이던 방송이 자동 복구 |
| **F. 사용자가 중지한 방송** | 방송 하나를 중지 → 서버 재시작 | 그 방송은 계속 `중지됨` |

### 이미 확인된 것

C·D·E·F는 리눅스에서 실제 RTMP 엔드포인트를 상대로 자동 실행해 확인했습니다.

```
TEST C  대시보드 3 / 3, 네 번째 → 402 max_concurrent_streams 한도를 초과했습니다 (3/3)
TEST D  6386 강제 종료 → 재연결 → 새 PID 6412. 나머지 두 개는 PID 그대로, RUNNING 유지
TEST E  서버 재시작 → "방송 2개를 복구했습니다"
TEST F  사용자가 중지한 방송은 재시작 후에도 desired=stopped / STOPPED
```

브라우저 전체 흐름(가입 → 업로드 → 대상 등록 → 방송 생성 → START → 브라우저
종료 후 재접속 → STOP)도 실제 Chromium으로 확인했습니다. 다시 돌려보려면:

```bash
npx playwright install chromium          # 처음 한 번
node scripts/browser-smoke.mjs --video ./어떤영상.mp4
```

## 안 되는 것 / 아직 없는 것

- **YouTube OAuth는 쓰지 않습니다.** 제목·설명 자동 설정, 자동 "실시간 시작"은
  데스크톱 앱에만 있습니다. 웹에서는 YouTube Studio에서 직접 키를 만들어 넣고,
  Studio에서 방송을 공개로 전환합니다.
- **예약 방송**은 웹에 없습니다(데스크톱에는 있습니다).
- **결제**는 없습니다. 요금제는 데이터베이스의 행이고, `--create-user --plan`로만
  바뀝니다.
- **저장 용량 한도**는 파일 하나 크기(`max_upload_bytes`)만 막습니다. 계정 전체
  합계(`max_storage_bytes`)는 기록만 하고 아직 거절하지 않습니다.
